# CLAUDE.md

Context for AI assistants working on this repo. Read this first. It is written so a new model can take over without the chat history.

## Project
ProClubs Tracker (Cantonese name: ProClubs 速查; formerly "FC 2X Pro Club Statistic Tracker"): a bilingual (zh-HK Traditional Cantonese / English) web app for EA Sports FC Pro Clubs. Live stats come from a server-side proxy to EA. An LLM explains comparisons that our code computes from live EA data (shared 15-minute cache). Nothing is saved per user. Full description is in `README.md`.

## Architecture Decisions (fixed by the brief)
- **Proxy, not a warehouse.** Fetch live from EA on demand. Do not store global player or club data.
- **No per-user club storage (decided 2026-11-13).** The user dropped the 'Saved clubs' / 'Snapshot' idea. Club data is fetched live from EA and kept in ONE shared 15-minute cache (`club_cache`) that holds EA data only, for everyone. **Never use the words 'Saved clubs' or 'Snapshot' in anything a user sees.**
- **AI input** is 1 to 4 clubs the user searched and added, loaded through the shared cache (live EA when missing or older than 15 minutes). One club: its statistics and members. 2 to 4: compare clubs, and members across clubs. Output is a short explanation of numbers our code computed, in the user's chosen language.
- **Bilingual is a core requirement.** It covers all UI strings and AI reports, not just the UI.

## Proxy (deployed to Vercel and verified 2026-11-11)
- The user confirmed all 10 proxy URLs return 200, and the validation checks return 400 (unknown endpoint, non-numeric club id). Not yet checked: 429 behavior, 60s cache timing, 503 block handling.
- Response bodies are still uninspected by the assistant (the user only reported status codes).
- `lib/ea.ts` holds the endpoint allowlist and `buildEaUrl`, which validates platform, numeric ids, matchType and clubName length before building the EA URL.
- `lib/rate-limit.ts` is an in-memory limiter, 30 requests per minute per IP. On serverless each instance has its own count, so it only blunts bursts, and the 429 path has never been tested live.
- **Rate limiter decision (2026-11-11, user agreed): do not set up Upstash now; deferred to M3.** Purpose: protect our access to EA (the main risk is EA blocking Vercel's shared IPs), the Vercel free-tier quota, and later LLM cost. The 60 s response cache probably does more than the limiter for repeat requests, but cache hits are **unverified**. In M3, rate-limit per user (logins exist then) using the Neon database or Upstash, and the AI endpoint in M5 needs its own stricter per-user limit. Unchecked: whether Vercel's built-in firewall rate limiting is available on the free plan and could cover the gap.
- `app/api/ea/[endpoint]/route.ts` is the live proxy: `GET /api/ea/<publicName>?platform=...&...`. It makes one upstream call with a 15s timeout and no retries. It caches 60s (`s-maxage` and fetch revalidate) and stores nothing.
- **Response envelope (changed 2026-11-11, BREAKING for any client of the old raw format):** `{ endpoint, parsed, parseError, raw }`. `parsed` is the typed, numeric result from `lib/ea-parse.ts` (`parseEaResponse`), `raw` is EA's untouched JSON. If a parser throws (EA changed a shape), `parsed` is `null`, `parseError` holds the message, and `raw` is still returned, so the route doesn't 500. `lib/ea-parse.ts` maps each endpoint to its parser; `playoffAchievements` is a passthrough. Keep `raw` while field meanings are unconfirmed. Dropping it later is a deliberate decision for the user.
- **Verified on Vercel (2026-11-11):** the user redeployed and `GET /api/ea/memberStats?platform=common-gen5&clubId=914493` returned `parseError: null`, `parsed` with real numbers (`"goals":"16"` became `16`), and `raw` intact. Checked live: memberStats, overallStats (two clubs). The other 8 are unit-tested against fixtures only. Errors: 400 bad input, 429 rate limited, 502 upstream error or non-JSON, 503 `upstream_blocked` (403 or a block-page pattern), 504 timeout.

- **Retries and reasoning effort (added 2026-11-12 at the user's request; mocked-fetch tests only, never run against Gemini):**
  - `LLM_MAX_RETRIES` (default **1**, range 0-3). Retries only a connection failure ("network") and HTTP 408/429/500/502/503/504/529. **Never retries a timeout** (the provider may still be generating and billing, so a retry could double the cost), a malformed or empty 200 response, or a client error (400/401/403/404/413/422: the same request would fail the same way). Backoff 400 ms, 800 ms, 1600 ms; honours `Retry-After` (seconds or an HTTP date) but refuses to wait more than 10 s and gives up instead; a retry is skipped if less than 3 s of the deadline would remain. **`LLM_TIMEOUT_MS` is now the TOTAL time for the whole call including waits** (each attempt gets only the time remaining); keep it at or under the route's `maxDuration` of 60 s (the config caps it at 55 s).
  - **Cost caveat:** a failed attempt that the provider nonetheless billed would be billed again by the retry. Whether Gemini bills a 429/5xx is **unverified**. The ledger records one row per analysis and uses the provider's usage from the successful attempt only, so **retried attempts are not counted in the app's cost**; the worst-case reservation is also computed for ONE call. Treat the app's daily cap as slightly optimistic when retries are on, and keep a spending limit at Google.
  - `LLM_REASONING_EFFORT` = `none|minimal|low|medium|high`; sent as `reasoning_effort` **only when set**. A mistyped or wrong-case value makes the service "not configured" (loud, not ignored). Whether a given Gemini model accepts it, and which values, is **unverified**; budget-checker passes the same five values. If the provider answers 400 to it, the user sees the generic "AI service unavailable" and the log shows the provider's sentence.
  - `LlmError` gained `retryAfterMs`, `detail` (the provider's sentence, first 200 chars, **server log only, never in `message`, never sent to the browser**) and `attempts`. `analyze` takes an optional `onLlmError` hook that the route uses to log; the successful result reports `usage.attempts`.
